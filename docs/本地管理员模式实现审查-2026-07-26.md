## 二、需要补充的实现（❌ / ⚠️）

### 2.1 【P0】TTL 到期自动清退定时器

**对应对计文档**：§7.1、§7.2

**当前状态**：`expires_at` 字段已写入 SQLite，但无 JS 级定时器，session 永不过期。

**缺失项**：

1. **`startTtlTimer()`** — 登录成功后启动 `setTimeout(remaining, forceLogout)`
2. **页面跳转刷新 TTL** — `beforeEach` 守卫中，非 PUBLIC_PAGES 的导航应刷新 `expires_at = now + ttlSeconds * 1000`
3. **`forceLogout()`** — 清除 session + toast 提示 + `reLaunch` 到首页
4. **`clearTtlTimer()`** — 登出时清除定时器

**影响**：当前登录后除非手动登出或重启 App，否则永不过期。与设计要求的「TTL 超时自动退回首页」不符。

**建议实现位置**：`uniapp/src/main.js`（`beforeEach` 中处理刷新）+ `uniapp/src/services/timer.js`（新建 TTL 管理模块）。

---

### 2.2 【P0】首次登录强制修改密码

**对应设计文档**：§7.4

**当前状态**：`password_state = 'ACTIVE'` 的凭据登录成功后直接进入管理页，但：
- 没有 `/pages/admin/change-password.vue` 页面
- `services` 中没有 `updatePassword()` / `changePassword()` 方法
- 没有 `needsPasswordChange` 标志处理

**缺失项**：

1. **`changePassword.vue`** — 新密码输入 + 确认页面
2. **`services.updatePassword(oldHash, newPassword)`** — PBKDF2 重新 hash + UPDATE `local_auth_credentials`
3. **登录后判断** — `password_state = 'INITIAL'` → 设置 `needsPasswordChange: true` → 跳转 change-password
4. **路由守卫拦截** — `needsPasswordChange == true` 时所有导航（除 change-password）拦截到 change-password

**影响**：当前超级管理员初始密码 `123456` 登录后不做强制修改。与设计要求不符。

### 2.3 【P0】二级密码校验接入路由守卫

**对应设计文档**：§12.4

**当前状态**：`local_secondary_password` 表已建 + 数据已 seed，但**无任何 UI 或路由拦截触发**。

**缺失项**：

1. **特权角色豁免** — `PRIVILEGED_ROLES = ['SUPER_ADMIN', 'DEVELOPER']` 跳过二级密码
2. **二级密码弹窗组件** — 独立的密码输入弹窗，6 位数字 + PBKDF2 比对
3. **路由守卫集成** — 当导航到需要 `admin.manage` 权限的页面时（如 role-manage、credential-manage），先检查特权角色 → 未命中则弹二级密码弹窗
4. **二级密码修改** — 管理页中修改二级密码的入口 + `services.updateSecondaryPassword(oldPw, newPw)`

**影响**：自定义角色获得 `admin.manage` 权限后可直接进入管理页，无二次校验。与设计要求的「自定义角色需要二级密码」完全不符。

### 2.4 【P1】动作级权限二次校验（assertPermission）

**对应设计文档**：§9

**当前状态**：所有操作均无条件执行，无 service 级权限检查。

**缺失项**：

`services/index.js` 中以下方法需要新增 `assertPermission()` 前置校验（具体 key 见设计 §9 表格）：

- `unlockSlot()` → 需 `cabinet.unlock`
- `unlockAllSlots()` → 需 `cabinet.unlockAll`
- `restartApp()` → 需 `app.restart`
- `restartDevice()` → 需 `app.restart`
- `upgradeApp()` / `upgradeFirmware()` → 需 `upgrade.*`
- `syncAuthorization()` → 需 `authorization.manage`
- `executeDebugCommand()` → 需 `debug.command`
- `registerFace()` / `registerFingerprint()` → 需 `biometric.register`

**建议实现**：
```js
const assertPermission = (perm) => {
  if (!hasPermission(perm)) {
    throw new Error(`Permission denied: ${perm}`)
  }
}
```

**影响**：菜单隐藏不等于安全。任何能拼出 `nativeBridge.request('serial.write', ...)` 的调用链都可以绕过前端菜单。

## 五、代码质量备注

### 5.1 值得肯定的设计决策

1. **localStore 层职责清晰**：`loginLocal` / `loadCurrentSession` / `refreshLocalSession` 分工合理
2. **权限解析递归正确**：`resolveRoleChain` → 展开角色继承链 → `resolvePermissionSet` → 展开权限层级 → `permissions` Set
3. **种子数据幂等性**：`checkInitializedCREDENTIAL_SEED_INITIALIZED` 避免重复初始化
4. **二次密码与凭据隔离**：`local_secondary_password` 独立存储，不混入凭据表
5. **super admin 激活保护**：`initSuperAdmin()` 只在设备激活成功后的首次初始化写入，不会覆盖用户修改

### 5.2 需要注意的风险点

1. **`services/loginLocal` 检查的是 `localStore` 而非 `localStore`** — 需确认当前 `services/index.js` 中的 loginLocal 实现确实委托给了 `localStore.loginLocal`（实测日志表明已委托 ✅）
2. **`PAGE_PERMISSIONS` 中可能有遗漏的未来页面** — 新增管理页时需同步更新
3. **TTL 存储的是 ms 级绝对时间戳** — 跨设备时区或时间跳变可能导致异常（当前单机场景无影响）
