### Mock bootstrap 分步交互重构（2026-07-25）
**问题**: mock `bootstrap()` 是单次全流程（register→activate→verify→getConfig→MQTT），但 splash.vue 期望分步交互：
1. `bootstrap({serverUrl})` → register → activate → emit WAITING_ACTIVATION_CODE → 返回
2. 用户输入激活码 → `bootstrapActivate(code)` → verify → getConfig → MQTT → success
3. 辅助方法: `bootstrapRetry()`, `bootstrapRefreshCode()`, `bootstrapCancel()`, `bootstrapDeviceInfo()`

**修复**:
- 添加模块级 `bootstrapState` 保存中间状态（code, token, registerCode, machineId, mqttPw）
- 提取 `continueAfterActivation()` 共享后续流程
- `bootstrap()` 在 WAITING_ACTIVATION_CODE 时保存状态并 `return`（不抛错）
- 添加 `bootstrapActivate(code)` 从保存状态继续验证
- `bootstrapRefreshCode()` 重新调 activate 获取新 registerCode
- `bootstrapRetry()` 清除状态重启流程
- **验证**: `build:verify` 6/6 PASS

### Bridge request 签名不匹配（2026-07-25）
**问题**: mock `bridge.request(service, action, args, options)` 与真实 `nativeBridge.request(action, payload, timeout)` 签名不同。
- Vue 调用 `request('storage.execute', { sql, params })` 时，`'storage.execute'` 被当作 service，`{ sql, params }` 被当作 action → "Unknown service: storage.execute.[object Object]"

**修复**: 重构 mock `request` 匹配真实签名：
- `request(action, payload, timeout)` — 从 `action` 字符串解析 `service.method`
- `requestAsync(action, payload)` — 同上
- 所有 handler 从 `(action, params[])` 改为 `(action, payload{})`：
  - `handleHttp`: `params[0]` → `payload.path`, `params[1]` → `payload.body`
  - `handleStorage`: `params[0], params[1]` → `payload.sql, payload.params`
  - `handleMqtt`: 新增 `send`, `loginStatus`, `handleMessage` 处理；`params[0]/[1]` → `payload.topic, payload.message`
  - `handleSerial`: 新增 `send`, `getLogs`, `subscribe`, `unsubscribe` 处理；均用 `payload`
  - `handleFace`: 均用 `payload`
- **验证**: `build:verify` 6/6 PASS
