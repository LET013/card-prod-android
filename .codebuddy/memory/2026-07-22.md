## 串口读不到数据修复（SerialManager 波特率 + 读取方式）
- **根因 1（波特率未传递）**: `SerialManager.open(String devicePath)` 硬编码 `BAUD_RATE = 115200`，不接受外部波特率参数。`SerialConnectionManager` 默认波特率 57600，调用 `open(port)` 时波特率被丢弃，实际以 115200 打开串口 → 波特率不匹配 → 读不到数据
- **根因 2（轮询读代替阻塞读）**: 旧版 `SerialManager` 使用 `Handler` + `available()` 轮询（10ms 间隔）。串口 fd 上 `available()` 经常返回 0（即使数据已到内核缓冲区），导致漏读。serial-debug 参考实现用的是独立 `ReadThread` 阻塞在 `inputStream.read()`，数据一到立即返回
- **修复**:
  - `SerialManager.open()` 签名改为 `open(String devicePath, int baudRate)`，移除硬编码波特率
  - 移除 HandlerThread 轮询逻辑，改为 `ReadThread`（独立 Thread，阻塞 `read()`，4096 字节缓冲区，`running` volatile 标志 + `interrupt()` 优雅退出）
  - `SerialConnectionManager.open()` 改为 `serialManager.open(port, baudRate)` 传递实际波特率
  - 补充 `SerialConnectionManager` 中缺失的 `TAG` 常量和 `android.util.Log` import

## SerialPort 重构：回归 serial-debug 的纯 JNI 壳层模式
- **问题**: `SerialPort` 把 `open()` 藏在构造函数里，`SerialManager.open()` 只 `new SerialPort(device, baudRate, flags)` 看不到显式的 `serialPort.open()` 调用，与 serial-debug 参考实现不一致
- **修复**:
  - `SerialPort`: 退为纯 JNI 壳层 → 无参构造 + `protected native FileDescriptor open(path, baudRate, flags)` + `protected native void close()` + `public native void tcflush()`
  - `SerialManager.open()`: 显式三步 → `new SerialPort()` → `serialPort.open(port, baudRate, 0)` → 手动创建 `FileInputStream`/`FileOutputStream` 从返回的 `FileDescriptor`
  - 移除 `catch (IOException e)`（`FileOutputStream(FileDescriptor)` 不抛 IOException）

## 启动卡死防护（SerialPort native 加载 + 诊断日志）
- **潜在原因**: `System.loadLibrary("SerialPort")` 在 `SerialPort` static 块中，若原生库未编译则抛 `UnsatisfiedLinkError`。`UnsatisfiedLinkError` 继承自 `Error` 非 `Exception`，`SerialConnectionManager.open()` 的 `catch (Exception)` 无法捕获，导致 Service 主线程崩溃
- **修复**: 
  - `SerialPort` static 块 try-catch `UnsatisfiedLinkError`，设置 `libraryLoaded` 标志；构造时检查并抛普通 `IOException`
  - 新增 `isAvailable()` 静态方法供外部检查
- **诊断日志**: `MainActivity.onCreate()` 每个步骤（initManagers/prewarmCameraX/...）加日志；`DeviceCoreService.onCreate()` 关键节点加日志

## 预绑定方案回退 → 常驻相机策略
- **根因**: 预绑定方案无效。`Preview.setSurfaceProvider()` 触发 CameraX 内部 `notifyReset()`，因为隐藏 PreviewView 和 Dialog PreviewView 的 Surface 不同，CameraX 必须拆除旧 CaptureSession 并创建新的，完整过程约 1.86s（含 Session close → open → stream），与原始 `bindToLifecycle` 几乎无差别

- **替代方案**: 「常驻相机」策略

  - `dialog_face_enrollment.xml`: 移除 PreviewView 和 loadingOverlay，仅保留底部状态栏 + 按钮
  - 首帧零延迟（相机已串流），Dialog 打开即可看到自己
  - `sClassesPrewarmed` 分离类预加载（一次性）和 Provider 绑定（每次 onCreate 重新绑定）
